# Evidence-driven contact strategy API workflow

`skills/contact_strategy/SKILL.md` describes contact-region selection, native sensor coverage review, sustained-load vs duration diagnosis, bounded adjustment and independent replay. It is in-context skill guidance, not model weight learning. Button numerical evidence is scoped to a single source/scene and supplied with provenance; `change_kind=reuse` distinguishes same-condition reuse from independent discovery.

Run button validation using `scripts/run_contact_strategy.py` with config/provider and the existing three credential arguments. Config binds output_root, config_path, baseline_case, dataset, geometry, experience, safety_bodies and hand_command_order. Each new run needs a fresh month/day/minute directory. The API may change preencoder, index fingers, tail0..5s and structured strategy only; decoder body outputs and gains remain unchanged. `contact_strategy.contact_audit` is saved-state contact measurement, not another physics simulation. It reports native success separately from all-right hand/wrist downward-force and hold. A physical gate plus exact saved token/hands replay is required. Legacy online feedback still reads native force; no claim that this has fixed palm-force feedback.

Run other-task forward tests using `scripts/run_contact_strategy_transfer.py`. Config includes button_gate pointing to the verified button summary, and task source bindings. This uses the SAME skill with an explicitly nonbutton capability profile: common translation of both wrists before mode1 encoding and tail0..3s; original fingers, no elbow/rotation controls, no postdecoder corrections. Task-native criteria apply. There are at most2 planned physical candidates/task. Unsupported actions/missing diagnostics are separately reported, not counted as physical failures. Successful native candidates get independent token+hands replay.

Both launchers load credentials into environment, rotate the three providers with existing bounded retries, use gpt-6-astra low, save request/response provenance and token accounting, and execute via pinned humano_python.sh. Videos are copied into the owning experiment's first level with hashes checked. Native false remains false even if a separate force diagnostic passes. Experimental source sequences are visible, so this is trajectory retargeting with evidence-guided contact strategy, not proof of strategy-only generation.

If a completed transfer study contains `needs_tool`, `scripts/run_contact_strategy_followup.py` consumes `{output_root, parent_study}` and automatically builds per-task saved-state diagnostics before another API decision. It records world-frame object forces by body, nearest target surfaces, and actual VR-point tracking relative to encoder commands. This is not a dynamics predictor and does not invent pelvis or foot control. Followup has a separately declared maximum2 candidates per diagnostic-request task; it excludes tasks that already exhausted their physical budget. Physical parameters remain API-authored. The generated execution_config binds provenance and actual capabilities.
