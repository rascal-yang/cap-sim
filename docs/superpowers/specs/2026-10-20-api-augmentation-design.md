# API 编排的独立 MimicGen 增广流程

创建时间：2026-10-20T22:03:48+08:00。
基线：`4ca42a2`，标签 `snapshot/pre-api-augmentation-20261020-2139`。
状态：用户已批准总体设计；本书面规格待评审。

## 目标与边界

用户通过任务输入，让模型 API 按需读取 skill、调用本地 Python 工具，
完成批量条件生成、规划、物理执行、验证和数据导出。稳定重复的工作由代码执行，
减少逐次人工编排和模型交互，记录真实调用次数与 token，不能未经测量宣称节省比例。
API 地址、协议、模型和凭据稍后由用户提供。

新增代码放在 `humanoid_mimicgen/augmentation/`，独立 CLI、测试、配置示例和
随仓库版本控制的 skill。复用 `humanoid_mimicgen/workflow/` 公共函数，
仅在必要且有回归验证时增补其接口；不修改其他数据生成路线。

保留当前确定性站位、导航、稳定判断、闭环纠偏、源手指动作及恢复策略。
默认禁止启用 `policy.grasp_trigger`，避免将旧的实时 Codex 判断意外带入增广。
模型编排不改变物理参数、验收阈值或控制模式。源轨迹可访问，研究分类明确为
`trajectory_retargeting`，不是无源动作的策略生成。

当前执行能力为 G1 / Dex3 / SONIC 1.0 / MuJoCo 的抓取、抬升和保持。
不将接口参数化描述成任意机器人、任务和物体均已支持。

## 已核实的基础与缺口

- `workflow/service.py` 已提供 plan、prepare、execute、inspect；
  prepare 冻结证据，execute 调用真实执行器与独立验证。
- `workflow/batch.py` 已能串行执行显式 case 清单，但不生成随机条件，
  不提供跨进程任务恢复或请求幂等；批次 completed 不代表每例成功。
- `workflow/decisions.py` 只有结构化站位建议，没有通用工具调用循环。
- `workflow/runner.py` 保存 states、observations、commands、contacts、
  events 和 execution_audit，不能把这些命令当作已保存的 SONIC token。
- `dataset.import_native` 面向旧的 attempts/success 格式，不能直接导入
  当前 workflow 目录。需要新增当前格式的导出适配器。
- `workflow/verification.py` 的结果保留 `training_ready=false`；
  新导出器不得以物理成功覆盖视觉验收状态。

## 架构取舍

采用“模型调用有类型的本地工具 + 持久化任务执行器”。
纯固定 HTTP 批处理不能满足模型按 skill 编排的要求；让模型直接任意运行
shell 则会重新引入大量上下文、不可复现命令和重复执行问题。
工具调用、Python API 和 JSON CLI 共用同一执行逻辑，不另建网页或远程部署。

模型 API 负责选择工具、读取精简状态和汇总。Python 负责参数校验、
采样、场景实例化、合同冻结、物理执行、恢复、验证、归档和统计。
一次批次提交覆盖多例；正常情况模型不参与逐帧控制，不逐例请求许可。

## 输入合同

版本化 JSON 任务包含：

- `schema_version`、调用者稳定的 `request_id`；
- 已有源示范和完整基线 workflow request 的路径；
- 增广条件：显式 case 列表，或带 seed、count 的范围采样；
- 机器人起始平面位置/朝向与目标物体平面位置变化，单位明确为米/弧度；
- 批次总案例上限、总墙钟预算、各例原有模拟/恢复预算；
- 输出根目录、是否渲染、导出选择；
- API 配置文件引用；密钥只通过配置指定的环境变量读取。

范围采样首先支持均匀平面采样，保存每例实际值及随机生成器版本。
源关节与原目标位置不默认一起平移；初始机器人和物体变换分别显式指定。
只在新案例初始状态构建时赋值，不在物理执行中重置状态。
初始穿透、绑定错误或不支持的自由度返回具体错误，不默默夹取到合法值。
桌高、不同模型和新任务需提供各自完整且有证据的基线 case，
首版不承诺自动修改这些物理条件。

基线中的 source/alignment/phases/control/acceptance 通过内容哈希绑定。
不依赖历史实验的绝对路径硬编码；示例可引用本机已存在的基线，
但入口允许用户提供其他符合能力约束的证据包。

## Skill 与工具协议

仓库自带可版本化的 `SKILL.md`，明确输入单位、流程、工具、
成功判据、错误处理和研究分类。启动仅发送目录摘要和必要约束，
`read_skill` 按需返回正文；日志绑定实际读取内容的哈希。
skill 是给模型的流程说明，执行限制由 Python 实现。
不默认读取用户的整个技能目录、聊天历史或整份仓库源码。

模型可调用以下有限操作：

1. `read_skill`：读取指定版本的增广 skill。
2. `validate_job`：校验任务、输入证据与支持范围，不推进物理。
3. `submit_job`：持久化并启动完整本地批次，返回 job ID。
4. `get_job`：返回精简进度、终态和产物索引；不返回完整轨迹。
5. `get_case`：按需读取指定案例的错误/验证摘要。
6. `export_job`：对已有结果导出，幂等，不重跑物理。

工具使用明确 JSON schema；拒绝未知工具、额外字段、非有限值和越界预算。
无任意 shell 工具。实际 Python 执行入口通过固定参数数组调用
`scripts/humano_python.sh`，遵循既定 HUMANO 运行环境。

可直接使用相同工具的 Python/CLI 入口运行固定任务，不强制所有批次经过模型。
模型工具循环有调用轮数、输出长度和墙钟预算，处理拒绝、未完成响应、
畸形参数和 API 错误；不得将模型文本“完成”当作物理成功。

## API 适配与节省上下文

先实现 Responses 风格的 function calling 传输层，与领域工具分离。
模型名称与 base URL 显式配置，不猜测用户未来接口支持何种模型或协议；
未知协议拒绝并报告，后续可添加独立适配器。
本地测试传输层采用脚本化响应，不使用真实账户凭据。

保存请求、工具调用 ID、结果摘要、服务端模型标识（若有）、usage、
API 等待时间、重试与错误类型。缺失 usage 为 unknown，不能当成零。
日志不保存 Authorization、密钥或完整环境变量。
按需发送 skill 和失败摘要，稳定工具定义复用，长任务在本地推进；
本地任务等待不依靠反复调用模型。

网络重试与物理重试区分：模型响应超时不能触发新的物理实验。
网络恢复沿用已持久化的工具调用/任务 ID。

## 持久化、幂等与批量执行

使用本地事务存储维护 job、case、工具调用和事件。
request_id 相同且规范化输入及文件哈希相同返回已有任务；
同 ID 不同内容明确冲突。工具 call_id 重复返回已有结果。

任务阶段：validated、queued、running、completed、failed、interrupted。
案例阶段包含 prepared、executing、verifying、exported；
保存阶段开始/结束及失败原因。总批次状态、完成案例数、
物理成功数、拒绝数和运行错误数分开报告。

单 GPU 物理执行串行且有跨进程排他锁。活动 worker 需要实际进程身份和
存活证据，不能只依据遗留锁文件判活。执行中断后先检查已保存的终态证据，
存在完整执行产物则验证/导出；无法确认完成则标记 interrupted，
不自动把中间物理状态恢复当成同一条完整成功轨迹。
未执行案例可继续；重做中断案例必须生成新的 attempt 与实验记录。

每例继续执行完整的 prepare/freeze/provider/hash 流程。
新实验目录按实际 Asia/Shanghai 创建时间命名，重复分钟加序号。
记录规划、准备、模拟、模型等待、验证、渲染、导出和总墙钟；
未测量值为 null。不得跳过实验合同来加速。

## 导出与结果语义

输出数据集索引和每例可校验的独立包，包含：

- 实测状态及时间、实际执行命令及其时间对应关系；
- 阶段/事件、接触、验证结果、模型/代码/skill/输入哈希；
- 随机条件、种子、运行时间和源轨迹访问声明；
- 可选视频的路径、哈希与视觉验收状态。

检查状态与命令的真实记录时序，显式保存状态在动作前/后的约定，
不得靠截断到最短数组伪造对齐。未执行的 attempted_commands 与
实际 commands 分开，失败终态保留在失败数据中。
物理成功数据与失败数据分区，汇总包含所有案例，不能丢掉失败降低分母。

首版交付通用 NPZ + JSON 轨迹包与索引，不宣称是 HUMANO 原始训练格式
或 SONIC token 数据集。缺失 token 明确标记；视觉未验收保持 false/unknown。
成功导出是结构及来源校验通过，不等于已获得最终视觉训练质量认证。

导出使用临时目录后原子发布，验证文件哈希；重复导出不覆盖不一致产物。
同一已成功完成任务重复提交/导出不新增物理步骤。

## 验收与测试

1. 参数及采样测试：相同 seed 得到相同 case；机器人/物体变化独立；
   非法单位、预算、绑定及不可支持的变换明确失败。
2. 工具循环测试：模拟 API 读取真实 skill、调用真实调度工具；
   验证多轮调用、重复 call_id、超时、无 usage、畸形参数与未知工具。
3. 恢复测试：重复请求、输入哈希变化、竞争提交、活跃 worker、
   worker 中断及导出中断；证明不会自动重复物理执行。
4. 离线导出测试：使用现有真实 workflow 记录，验证状态/动作对齐、
   成败分类、阶段、哈希、模式和视觉验收语义；模拟响应不冒充真实 API。
5. 回归：workflow、历史 MimicGen 与核心相关测试；核对其他路线源码不变。
6. 小批量真实仿真：完成新合同后通过新工具入口运行已支持的案例，
   检查 provider/模型、控制模式、成功率、时间和产物；失败也必须正确归档。
   不以单例成功推断总体可靠性，不混同之前要求的十条件控制器比较。
7. 用户提供 API 后真实联调：验证 skill 读取、工具请求、完整批次、
   结果导出及真实 usage；此前只报告本地与模拟协议验证完成。

不把真实 API 尚未联通、训练导出缺失或只通过 mock 测试描述为全目标完成。
