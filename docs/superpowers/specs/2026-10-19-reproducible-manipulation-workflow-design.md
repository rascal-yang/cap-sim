# 可复现的导航与接触轨迹复用流程

日期：2026-10-19（Asia/Shanghai）
状态：设计待审阅，尚非实现或物理验证结果。

## 1. 已确认的需求

用户要求将导航后接触轨迹复用落成结构化、可供后续 API 调用的代码；去掉针对单次实验的特殊超参数；可确定计算的部分落代码，尚不能可靠规则化的策略决策交给 API；尽量保存策略，保证可复现。保持其他管线及历史实验执行器不变。

“通用”指相同接口在声明支持的场景中完成计算，或明确返回缺失数据、不可达、不支持、需要标定、规划失败等结果，不是任意物理任务均能成功。不得把试验专用数值搬进配置后宣称已经通用。

成功的历史证据：`experiments/20261019_1820_apple_nav_wrist_feedback_y_minus15`。其中前移8cm、反馈增益0.5/s及上限2cm仅是历史配置，不成为新流程的默认值或自动回退值。该成功属于原轨迹可见的轨迹重定向，不能宣称已实现独立策略生成。

## 2. 方案选择

选择：显式机器人适配器 + 确定性计算工具 + 受约束的结构化 API 策略 + 不可变策略包。

不选择把旧执行器直接包成 HTTP 服务：仍会保留固定帧号、对象索引和特殊站位。不选择每个控制周期调用模型：网络延迟不可预测，也难以复现。第一阶段提供 Python/JSON CLI 接口；HTTP 服务之后薄封装同一入口，不在本次增加部署、认证或队列系统。

实现范围为当前 G1/SONIC 的原生仿真适配器及独立流程接口。其他机器人通过相同能力接口接入；缺少适配器必须返回 `unsupported_capability`，不得落回 G1 关节布局。

## 3. 输入与职责边界

### 任务输入

- 场景与机器人模型、对象/末端名称、初始状态及哈希。
- 已标注示范、阶段起止、源对象坐标系、原命令与测量的时间对应关系。
- 当前任务目标、接触语义与成功定义。
- 机器人及控制器能力声明、限制来源、标定证据。
- 仿真/规划/API预算；API模型、提供方、超时设置；可选已保存策略摘要。

单位与坐标系必须显式：米、秒、弧度、牛顿、世界/物体/机器人坐标系及四元数约定。缺少数据是 unknown，不补零。状态闭区间与命令半开区间分别表示，公共边界状态不导致重复执行命令。

### 确定性代码

负责数据解析、坐标变换、阶段边界校验、FK/IK、碰撞与可达性检查、路径生成、时间参数化、执行状态机、控制器反馈、物理停止条件与结果验收。

机器人关节/对象通过名称和模型结构绑定，禁止固定 qpos 索引；阶段通过语义标注绑定，禁止1599、1880等示范专用帧号；操作手来自策略与适配器能力声明。

站位优先验证当前姿态和示范物体坐标系变换得到的名义姿态。其他候选来自具有来源的几何搜索或 API。候选必须通过实际模型的可达性和路径检查；不添加固定8cm或固定偏移网格。可行候选以明确的字典序比较移动需求、路径长度、朝向偏差，避免隐含加权常数。

数值求解容差、碰撞离散精度属于算法设置，物理限制属于设备设置，任务成功标准属于任务输入，必须分别记录来源；不能混为“零参数”。

### API 策略

负责候选操作手/接近方向/站位、示范片段选择、失败解释及恢复动作建议。输入为当前证据和可调用能力清单；输出仅限结构化动作图、候选参数、引用的证据及预期条件。

API 不输出任意可执行 Python、shell 或文件路径；不改质量/摩擦/碰撞条件，不越过阶段门，不把未执行候选标记为成功。候选参数不是已获证明的物理事实。输出必须通过schema、能力、引用和几何验证。

API 不能代替控制器标定。缺少稳定性、响应或可执行修正范围证据时返回 `needs_calibration`。API可以提出标定/新观测计划，不能凭空给增益后称已标定。高频反馈不依赖API请求；其设置从控制器能力与实际标定推导并保存推导证据。不能推导时停止准备，而不是悄悄采用历史0.5/2cm。

## 4. 流程与公开接口

建议 Python API：

```python
proposal = workflow.plan(request)       # 确定性优先；按需调用API；无物理执行
prepared = workflow.prepare(proposal.strategy_id, request)
result = workflow.execute(prepared.experiment_id)
status = workflow.inspect(prepared.experiment_id)
```

CLI与Python共用实现，以JSON输入、JSON结果输出；调试日志独立输出。接口中不允许未经校验的运行时参数覆盖冻结合同。

执行状态：

```text
validate_inputs → resolve_strategy → validate_geometry → freeze_contract
→ navigate（若需要）→ settle → observe_and_replan
→ approach → contact_phases[] → verify → completed / failed
```

`contact_phases`由标注产生，并非固定只能抓取/抬升/保持。每个阶段保存起始状态、目标来源、前置条件、结束条件、实际命令、观测和结束原因。阶段边界以实测条件判断，源时间只是参考进度，不是接触成功证据。

停稳检查底座运动与双脚支撑，随后从实测状态重规划；不以“原手部保持目标误差”阻止新的实测接近规划。站立参考的来源与适配方法必须可解释、可校验，不能未经检查套用某个示范的腿姿。

失败后保存检查点和证据，可向API请求恢复策略；恢复提案必须重新校验。改变控制接口、目标、预算或物理设置时创建新冻结尝试，禁止改写正在执行的合同。新尝试从何种实际终态或初态启动必须显式，不隐式瞬移、重置或重复抓取。

## 5. 策略包与可复现性

建议存放于 `humanoid_mimicgen/strategies/<strategy_id>/`；实验仍使用仓库规定的北京时间分钟ID。策略ID来自规范化策略内容的SHA256，文件不可原地改写；变更生成新ID，记录parent_id、变更原因与证据。摘要用于完整性校验，不用于证明策略有效。

每个策略包至少包含：

- `strategy.json`：schema版本、策略图、对象/操作手语义、坐标系、前置/结束条件、参数来源及适用条件。
- `manifest.json`：输入、模型、适配器、代码、技能、提示词、配置、标定数据的摘要与可移植相对引用。
- `decisions/`：API请求、提示词、原始响应、解析后提案、schema验证及拒绝原因；记录模型请求名/返回名、调用时间、用量、随机种子（若提供方支持）、错误。
- `validation/`：几何检查、标定推导、生成命令核验；明确无物理步的检查不能证明物理成功。
- `execution_refs.json`：关联实验ID及报告，不将成功结果写回覆盖策略定义。
- `experience.json`：observed/replicated/rejected等状态、适用对象/机器人/控制器/接触条件和反例。

凭据仅从运行环境读取，不进入策略包、请求日志或异常文本。API失败要留调用记录，不自动切模型、不伪造提案、不静默回退历史策略。环境或文件引用含敏感数据时应在调用前限定证据字段。

### 三种重用模式

1. **决策复现**：加载已保存策略及API响应；禁止网络调用；核验全部依赖后重新做确定性检查。
2. **执行复现**：同一策略、初态、物理、控制器、种子和预算，创建新实验进行物理运行。记录差异与结果，不保证跨硬件逐位一致。
3. **策略迁移**：更换物体/场景/初态，生成带parent_id的新策略实例；重新验证，失败时API可生成新修订。不得直接沿用旧场景的world坐标或几何通过标记。

未知/缺失哈希、模型版本漂移、缺失标定均阻止声称严格复现。固定模型名或temperature不保证API返回相同策略，所以决策复现使用保存响应，而非重新请求模型。

## 6. 结果与失败结构

统一结果含schema版本、task_id、strategy_id、experiment_id、status、stage、reason_code、证据引用、实测指标、实际控制模式及视频路径。

至少区分：invalid_input、unsupported_capability、needs_observation、needs_calibration、api_unavailable、invalid_api_proposal、unreachable、planning_budget_exhausted、preflight_failed、navigation_timeout、settling_timeout、collision、contact_lost、execution_error、verification_failed。

`completed`指任务的实际验收通过，不等同于程序正常退出。物理成功、原生checker结果、视觉验收和training_ready分别输出。未执行阶段指标为null，不填0。失败记录保留，禁止只保存成功样本。

## 7. 实现边界与兼容

新增 `humanoid_mimicgen/workflow/`，建议职责划分：contracts、strategy_store、decision_provider、planner、executor、adapters/native_sonic、cli、verification。可以在实现计划中合并过小文件，但数据/决策/执行边界必须保留。

旧实验模块、冻结源码及其他管线不修改；现有纯计算函数只在不存在示范专用常量且接口满足要求时复用。历史成功配置可作为显式historical_reproduction测试夹具，不能成为通用路径默认值。新增接口与现有离线标注/生成命令并存。

所有新物理尝试遵循 `docs/experiment-records.md` 和模板：准备证据、真实模型加载检查、代码/输入哈希、实际控制接口和预算齐全后才冻结启动。HUMANO运行使用指定wrapper及已要求版本，无隐式mode0/IK执行回退。IK作为参考规划与IK直接执行明确区分。

本设计不把正式十条件对照缩减为一次回归。若开展方法对比，仍使用AGENTS指定的最近十条件并声明不可避免差异；接口回归不能被描述为完成十条件比较。

## 8. 验证与完成条件

- 更换阶段名称/帧范围/操作手/对象名称后，编译和验证不依赖旧苹果实验常量。
- 同内容产生相同策略摘要；任一依赖变更被识别；并发写入不覆盖；损坏/缺失依赖明确拒绝。
- 保存响应重放时不调用API；新场景必须重新验证，不复用旧几何结论。
- 验证真实API客户端的请求、响应、超时、畸形输出和缺失凭据处理；测试桩验证不冒充真实API调用成功。
- 每个阶段正常/异常转换有测试；碰撞和接触丢失终止后不继续下发动作；不支持能力无回退。
- 标定不足不能使用历史反馈常数；可用标定需核验来源、适用范围及计算结果。
- 原生适配器必须真实调用控制器并记录测量，不能以空接口或录制轨迹回放冒充新的物理执行。
- 至少一次经过冻结合同的新端到端物理验证，检查阶段、源接触命令对应、实际模式、接触/保持指标，并保存完整解码的双视角MP4与反思。仅测试通过不足以声称执行完成。
- 保留可运行JSON示例、Python/CLI入口说明和保存策略重放命令；不依赖/tmp文件或私人绝对路径。
- 成功报告明确物理验证覆盖范围；视觉时序验收未完成时training_ready仍为false。

## 9. 设计审查结论

本设计没有“任何环境必成功”的承诺；通用接口与原生适配器支持范围已分开。策略版本可复现与物理逐位复现已分开。特殊经验常数不得通过更名配置项保留。缺少标定/能力时的错误返回是必要行为，但不能把缺少实际执行适配器的框架交付成已完成管线。

下一步是用户审阅此设计；通过后制定实现计划，再实现及验证。本文不是已经实现的接口文档。
