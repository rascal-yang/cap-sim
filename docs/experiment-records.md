# 统一实验记录规范

每次物理实验必须先完成 `experiment.json`，从 [JSON模板](experiment-record.template.json)复制填写。新批次目录使用 `experiments/YYYY-MM/DD/YYYYMMDD_HHMM_<description>/`（月／日／单次实验），子案例证据归属各批次。历史目录已按用户要求实际迁入月／日，外层不保留兼容链接。旧路径映射见 `experiments/_index/latest-migration.json`；冻结记录内容不改写，重跑前需解析旧路径。未知日期放 undated，不按修改时间推断。目录编号和报告使用北京时间 `YYYYMMDD_HHMM_名称`；同分钟重名加序号。模板中的 null 必须填写或明确说明不适用，不能作为已通过检查的证据。

## 执行前冻结

1. **目的与对照**：写出待检验假设、历史基线目录、精确场景清单、唯一计划变化、必须保持一致的条件。区分“替换控制接口对比”和“重新规划策略”，不能同时修改后再归因于控制器。
2. **物理接口**：记录仿真器版本、机器人/手/物体资产、初态及配置哈希、物理步长、控制频率、PD参数、质量、惯量、摩擦、动作权限、碰撞停止条件和独立验收程序/阈值。文件路径和SHA256同时保存。
3. **控制接口**：逐阶段记录动作字段、单位、坐标系、四元数顺序、插值方式、控制器模式、下半身planner和上半身接口。明确是否使用IK、mode0全身参考、mode1 Cartesian teleop、原始motion token前缀；混合接口不能简称“全程teleop”。保留前缀须记录来源、时长与哈希。
4. **运行环境**：固定TensorRT **10.13.0.35**、ONNX Runtime **1.23.2**、SONIC **1.0原始发布模型**，encoder/decoder/planner全部 **CPUExecutionProvider**。另记Python、MuJoCo和gear_sonic包装包版本（当前0.1.0，不能写成模型版本1.0）。TensorRT存在不等于用于推理，渲染GPU与推理设备分别记录。
5. **pipeline**：保存实际入口、执行顺序、源码快照或可恢复补丁及SHA256、任务skill版本/哈希、提示词/规划器身份、是否调用外部模型、是否访问原动作序列、阶段门、反思与重试规则、优化开关和预算。仅Git提交号不足以标识未提交代码；说明性CaP伪代码不能代替实际入口。
6. **对比指标**：记录位置/朝向目标的来源、坐标系、采样时刻、单位和计算方法。分开统计静态IK残差、相对插值指令的实际跟踪误差、相对最终目标的到达误差；提前停止时不能混用。位置用米，旋转用相对旋转角（弧度）；报告阶段末端和可获得的逐帧RMSE/P95/最大值。逐帧指标缺失写未知。另记根部漂移、接触、碰撞、成功及实际执行时长。比较共同执行阶段，并单列失败截断和覆盖率，不把未执行阶段当零误差。

使用统一启动入口，并在实验目录保存实际模型加载检查：

```bash
./scripts/humano_python.sh scripts/check_humano_runtime.py --load-models --out "$RUN_DIR/runtime.json"
```

启动前逐项比对基线与本次配置，保存 `comparison_diff.json`；物理、验收或目标含义出现未声明变化时停止。旧实验无法证实的字段标为未知，不回填成当前版本。若旧基线运行环境不同，明确这是历史比较的混杂因素，不能声称严格仅控制接口不同。

## 执行与结束证据

- 冻结后记录契约文件SHA256。每次尝试记录开始/结束ISO 8601时间（含+08:00）、场景ID、初态、动作与目标、实测状态、实际网络模式/provider、失败阶段与原因、反思和下一次具体变化。
- 发现实际接口偏离契约立即停止并保留诊断，不自动回退到IK或其他模式。允许反馈修改哪些通道，应在契约中预先写明；修改冻结控制接口/物理/验收需要新的实验ID。
- 保存 `execution_audit.json`，对照契约检查实际执行。成功先保留；优化仅按本批明确预算执行。规划、仿真计算、仿真时间、渲染及总墙钟时间分别记录，未计时项标未知。
- `REPORT.md`开头固定展示：实验ID与起止时间、目的与基线、运行环境、各阶段控制接口、pipeline/skill版本、本次变化、执行审计结果。成功次数同时写分母与场景数，不能混淆重复尝试和不同场景。

当前这份规范是执行工作流要求与记录模板，**尚不是核心运行器自动校验全部字段的功能**。已有运行环境检查可以直接使用；实验入口需落实其余检查并保存证据，不能仅凭填表宣称符合。

## 下一轮已确认的对照范围

基线为 `experiments/20261013_apple_straight_sweep` 的十个条件：Y−10、+10、−15、+15、−20、+20cm，以及桌面与苹果一起升高/降低7.5、10cm。Y+10cm使用恢复原接触门后的有效执行；误加固定食指门的执行另列。Y−10cm当时仍使用误加门版本，必须披露该策略差异，不能把整批称为严格单一策略基线。

新组以SONIC teleop替换右臂IK/mode0生成抓取阶段；原token接近前缀若保留必须明示。固定原场景、初态、物理、手指指令、目标、时长及验收，不同时加入新站位、新抓法或减速优化。teleop需要的双腕、躯干与骨盆目标来源、模式交接和插值规则必须在执行前明确；无法精确匹配的通道列为对比限制。
